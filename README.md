# 야구일기 V7.9.0

야구일기는 한 선수의 경기·훈련·투구·타격·수비·주루를 한 공 한 공 쌓아 보는 오프라인 우선 PWA입니다.

V7.9.0은 투구·타격·주루·수비에 같은 경기 상황 입력기를 적용하고, 매 공·플레이·도루에 당시 아웃 카운트와 주자 상황을 저장해 상황별 성과를 분석합니다. 데이터베이스 스키마와 Supabase SQL은 변경하지 않습니다.

## V7.9.0 공통 경기 상황

- 투구·타격은 현재 투타 조건 아래, 주루는 입력 화면 상단, 수비는 플레이 시작 상황에 같은 UI를 사용합니다.
- 아웃 카운트는 `미입력 / 0아웃 / 1아웃 / 2아웃`, 주자 상황은 `미입력 / 주자 없음 / 1루 / 2루 / 3루`를 구분합니다. 1루·2루·3루는 모바일에서도 한 줄에 표시하고 복수 선택할 수 있습니다.
- 별도 상황 변경 버튼이나 변경 사유는 입력하지 않습니다. 상황이 달라졌다면 다음 기록 전에 현재 상황을 바꾸며, 각 기록은 저장 당시 상황을 독립적인 스냅샷으로 보존합니다.
- 한 타자·타석 도중 상황이 바뀌어도 공마다 다른 상황을 저장하므로 변경 전후 투구·타격을 정확히 분리합니다. 한 공 수정과 도루 기록 수정에서도 당시 상황을 보완할 수 있습니다.
- 분석에는 투구의 상황별 Strike%·CSW%·K%·BB%, 타격의 상황별 AVG·OBP·SLG·OPS·Contact%, 주루의 상황별 시도·성공률이 추가됩니다. 완료 BF/PA 결과는 마지막 공의 상황에 귀속합니다.
- 기존 기록은 상황 미입력으로 유지하며 실패로 계산하지 않습니다.

## V7.8.1 경기 수비 입력 정리

- P/C/1B/2B/3B/SS/LF/CF/RF를 같은 방식으로 선택합니다. 선택형 `플레이 시작 상황`에서 0·1·2아웃과 주자 없음·1루·2루·3루를 입력하며, 입력·수정 화면이 같은 편집기를 사용합니다.
- 타구 처리는 타구 종류·선수 기준 방향·속도·처리 결과를 기록하고, 땅볼·번트일 때만 정면·포핸드·백핸드를 추가로 선택합니다.
- 송구는 목적지·정확도·부하로 단순화했습니다. `매우 가벼움`은 송구 횟수에는 포함하지만 TLU는 0입니다.
- 송구 받기는 받은 위치·보낸 포지션·송구 형태·방법·결과를 분리합니다. 받을 수 없는 송구는 수신 실패가 아니라 평가 제외로 처리합니다.
- 태그·베이스 터치·커버·백업의 수행 항목은 유지하되 중복된 세부 정보는 제거했습니다.
- 플레이 종료는 잡은 아웃 수와 플레이 후 남은 주자를 따로 입력합니다. 공식 기록은 `공식 기록 없음` 또는 PO/A/E/DP를 반드시 명시해야 저장할 수 있습니다.
- 분석에서는 REACH%와 ON-TIME%를 제거하고, 타구 방향·속도·처리 방법, 수신 출발 포지션·형태·방법, 송구 목적지·부하, 태그·베이스 대상, 커버 역할과 포지션별 결과를 제공합니다.
- 플레이 시작 아웃 카운트·주자·득점권 분포와 상황별 타구 최종 처리율·송구 수신 가능률·실책을 표본 수와 함께 제공합니다. 이 값은 개인 수행 스플릿이며 OAA·UZR 같은 범위 기반 공식 지표로 사용하지 않습니다.
- V7.7 이하 수비 기록은 강제 변환하지 않고 기존 형식으로 표시하며, 수정 후 저장할 때만 새 형식으로 전환합니다.

## V7.7.0 수비 훈련 시나리오

### 간단 기록과 시나리오 기록

- `간단 기록`은 기존처럼 훈련 종류, 내야·외야, reps, 실제 송구 수, 송구 부하를 빠르게 저장합니다. 기존 수비 훈련 기록은 자동 변환하지 않고 이 방식으로 안전하게 표시합니다.
- `시나리오 기록`은 타구 처리, 송구 받기, 주자 태그, 베이스 터치, 송구, 커버·백업을 실제 훈련 순서대로 반복해서 구성합니다.
- 중간 동작 삽입·삭제·종류 변경·앞뒤 이동을 지원합니다. 각 동작의 실제 횟수를 비워 두면 시나리오 reps와 같게 계산하고, 필요한 단계만 별도 횟수로 덮어쓸 수 있습니다.
- 송구 동작마다 `0.00`, `0.75`, `0.85`, `1.00 TLU`를 따로 선택합니다. 매우 가벼운 토스는 송구 횟수에는 포함하되 TLU에는 더하지 않습니다.
- 선택 항목인 훈련 결과는 `목표대로`, `보완 필요`, `실패·중단`으로 입력합니다. 일부 reps만 평가할 수 있으며 미평가 reps는 실패와 분석 분모에 포함하지 않습니다.

### 훈련 기록·수정 UI

- 투구·타격·수비·주루 훈련 기록을 모두 `훈련량 배지 | 기록 요약 | 펼침 화살표` 카드로 표시합니다. 입력 시각과 수정·삭제 버튼은 접힌 카드에서 숨깁니다.
- 펼친 카드 아래에 종목명이 명시된 `훈련 수정`, `훈련 삭제` 버튼을 경기 기록과 같은 크기·색상·모바일 2열 구조로 표시합니다.
- 모든 훈련 수정은 공통 하단 시트를 사용합니다. 수비 훈련은 입력 화면과 동일한 간단·시나리오 편집기를 재사용합니다.

### 훈련량 중심 수비 분석

- Sets, Reps, Action Reps, Throws, Throw TLU, TLU / Rep을 핵심 훈련량으로 표시합니다.
- FIELD, RECEIVE, TAG, BASE, THROW, COVER의 동작별 reps와 시나리오 흐름, 포지션, 타구 종류, 송구 목적지, 송구 부하를 분해합니다.
- 선택 평가를 입력한 경우에만 Evaluated Reps, Target%, Adjust%, Failure%를 계산합니다.
- 간단 기록과 기존 기록은 전체 reps·throws·TLU에는 포함하지만, 알 수 없는 동작별 reps를 임의로 추정하지 않습니다.

## V7.6.1 분석·입력 UI 보완

- 수비 훈련 송구 부하에 `매우 가벼운 토스 · 0.00`을 추가했습니다. 송구 횟수는 유지하되 TLU에는 더하지 않으며, 신규 입력과 기록 수정에서 같은 선택지를 사용합니다.
- 수비 훈련 기록 카드에는 토스도 `송구 횟수 · 0.00 TLU`로 표시해 송구 미실시와 구분합니다.
- 1타석 1볼넷·1사구처럼 타수는 0이지만 출루 기회가 있는 경우 SLG를 `.000`으로 표시하고 OPS에 OBP를 반영합니다. 기록이 전혀 없으면 기존처럼 `—`를 표시합니다.
- 분석 상단 영문 제목을 `ANALYSIS DASHBOARD`로 맞췄습니다.
- 기록 검색 조건 전체에 분석과 같은 외곽 카드 테두리·그림자·반응형 여백을 적용했습니다.
- 경기 투구·타격의 B/S 카운트와 볼·스트라이크·인플레이 버튼을 하나의 결과 입력 카드로 묶었습니다. 결과 미상·강판·ARM LOAD는 실제 투구 결과와 구분해 카드 밖에 유지합니다.

## V7.6.0 직접 아웃 동작

- 동작 선택은 `타구 처리`, `송구 받기`, `주자 태그`, `베이스 터치`, `송구`, `커버·백업`의 6가지입니다. 같은 동작을 반복하거나 플레이 중간에 삽입할 수 있습니다.
- 주자 태그는 태그 대상(선택), 실행 결과, 타이밍, 심판 판정을 서로 분리해 저장합니다.
- 베이스 터치는 목표 베이스, 접촉 결과, 타이밍, 심판 판정을 기록하며 포스·어필 같은 플레이 목적은 선택 항목입니다.
- `판정 없음`은 미입력이나 실패와 다른 완료 상태입니다. 실행 실패, 늦은 타이밍, 아웃·세이프 판정도 서로 덮어쓰지 않습니다.
- 송구 뒤 재수신 없이 태그·베이스 터치를 넣는 등 공 소유 흐름이 맞지 않으면 해당 단계에 확인 경고를 표시하되 기록은 보존합니다.
- 직접 아웃 동작이 있으면 전체 결과의 태그·베이스 방식은 중복 입력하지 않아도 됩니다. PO·A·DP는 추천만 하고 사용자가 공식 기록을 직접 확정합니다.
- 기록 상세·수정·검색에 두 동작을 추가하고, TAG%, TAG OUT%, BASE%, OUT-TIME%, OUT-MISS% 자체 지표를 제공합니다.

## V7.5.0 수비 플레이 흐름

### 순서대로 반복하는 수비 입력

- 첫 동작으로 `타구 처리`, `송구 받기`, `송구`, `커버·백업` 중 하나를 선택합니다.
- 각 동작을 입력한 뒤 `여기서 플레이 종료` 또는 `다음 동작`을 선택합니다. 같은 종류의 동작을 여러 번 넣거나 순서를 바꾸는 것도 가능합니다.
- 타구 처리는 타구 종류·난도·도달 여부·처리 결과, 송구는 목적지·품질·타이밍·TLU, 송구 받기는 들어온 송구·수신 결과·받는 기술, 커버·백업은 역할·도착 시점·수행 결과를 분리해 저장합니다.
- 동료를 거쳐 우리 선수가 다시 참여하는 `송구 → 동료 선수 경유 → 송구 받기` 흐름을 기록에서 명확히 표시합니다.
- 플레이 상황과 각 동작의 판단 평가는 선택 사항입니다. 판단은 `최선`, `허용 가능`, `잘못된 판단`과 평가 근거를 함께 남길 수 있습니다.

### 실제 결과와 공식 기록 분리

- 마지막 동작 뒤 실제 플레이 결과를 `아웃`, `세이프`, `플레이 계속`, `미입력`으로 기록합니다.
- 아웃이면 아웃 방식과 기록한 아웃 수를 추가로 입력합니다.
- PO·A·E·DP는 기술 동작 결과로 자동 확정하지 않고, 공식 기록을 확인한 뒤 별도로 선택합니다. 앱의 추천은 참고 문구일 뿐 저장값을 바꾸지 않습니다.
- 공식 지표는 PO, A, E, DP, TC, FPCT로 따로 표시하고, 도달률·최종 처리율·정확 송구율·수신 성공률·판단 적절률은 앱의 과정 분석 지표로 명시합니다.

### 기록 검색과 완전한 수정

- 접힌 수비 카드는 기존 기록 UI와 같은 `색상 결과 | 포지션·동작 흐름 | 펼침 화살표` 구조를 사용하고, 대표 결과는 최대 두 개만 표시합니다.
- 펼치면 모든 동작의 순서와 세부 값, 플레이 결과, 공식 기록, 판단 평가, 송구 TLU를 확인할 수 있습니다.
- `수비 기록 수정`은 입력 화면과 같은 전용 편집기를 사용합니다. 동작 추가·삭제·종류 변경·순서 이동과 미입력 값 보완이 모두 가능합니다.
- 필수값을 모르는 경우에는 미입력 상태로도 저장할 수 있으며, 카드와 기록 검색에서 `미입력 있음`으로 찾을 수 있습니다. 공식 기록 미입력과 기존 형식 기록도 별도 조건으로 찾습니다.
- V7.4.2 이하의 수비 기록은 삭제하지 않고 기존 형식으로 읽습니다. 처음 수정해 저장할 때 새 순차 동작 형식으로 전환합니다.

## V7.4.2 도루 기록 수정

- 도루 기록 수정창에서 기존 출발 베이스, 도착 베이스, 성공·실패 값을 선택된 상태로 불러옵니다.
- 출발 베이스를 바꾸면 다음 베이스가 자동으로 맞춰지며 각 항목을 다시 선택할 수 있습니다.
- 수정한 경로와 결과를 `gameEvents.metadata`에 저장하고 기록 카드·구간별 도루 분석에 즉시 다시 반영합니다.
- 한 베이스 단위가 아닌 동일·역방향·두 베이스 건너뛰기 조합은 저장하지 않습니다.

## V7.4.1 UI 일관성 패치

- 경기 기록 카드는 종목과 화면 크기에 관계없이 `결과 | 기록 요약 | 펼침 화살표` 순서를 사용합니다.
- 수비와 도루도 투구·타격처럼 오른쪽 화살표로 펼친 뒤 수정·삭제할 수 있습니다. 접힌 카드에는 동작 버튼을 노출하지 않습니다.
- 모든 수정·삭제 버튼에 `투구 기록`, `타격 기록`, `수비 기록`, `도루 기록`을 명시하고 같은 모양·간격·터치 높이를 적용했습니다.
- 투구 카드의 잘못된 `타자 기록 삭제` 문구를 `투구 기록 삭제`로 바로잡았습니다.
- 왼쪽 색상 결과 영역은 PC·태블릿에서 80px→56px, 모바일에서 72px→50px로 약 30% 줄여 가운데 기록 내용에 더 많은 공간을 배정했습니다.
- 기록 상세 조건의 `조건 초기화` 버튼은 제거했습니다. 경기/훈련이나 종목을 바꿀 때 적용할 수 없는 조건만 기존처럼 안전하게 자동 초기화합니다.

## V7.4.0 핵심 변경

### 결과 중심 기록 카드

### 계정별 IndexedDB 완전 분리

로그인 UID별로 별도 DB를 사용합니다.

- A 계정: `baseball-diary-v7:<A_UID>`
- B 계정: `baseball-diary-v7:<B_UID>`

로그아웃하면 동기화 타이머를 중단하고, 활성 DB를 닫고, 화면 메모리와 모달 내용을 비웁니다. 이후 B 계정으로 로그인하면 B 전용 DB만 열기 때문에 같은 아이폰·태블릿을 번갈아 사용해도 A 기록이 B 화면·분석·백업에 나타나지 않습니다.

저장 모듈도 현재 UID와 다른 `ownerId` 행의 쓰기를 거부합니다. 서버에서는 기존 `owner_id` RLS가 별도의 보호벽으로 동작합니다.

### 기존 기록의 안전한 1회 이전

V6의 전역 IndexedDB `baseball-tracker-v6` 또는 V5 로컬 기록을 발견하면 자동 귀속하지 않고 먼저 미리보기를 표시합니다.

- 선수 수
- 경기 일수
- 경기 이벤트 수
- 훈련 세트 수
- 기록 기간

`내 계정으로 이전`을 선택한 경우에만 현재 UID로 복사하고 동기화합니다. 기존 전역 DB는 자동 삭제하지 않습니다.

기존 전역 DB에 여러 계정이 섞여 있으면 현재 UID 소유 행과 그 선수·경기 관계로 소유자를 확인할 수 있는 행만 분리해 미리보기에 표시합니다. 다른 계정 행은 읽거나 이전하지 않습니다. 현재 계정으로 확인되는 행이 하나도 없으면 기록 수나 선수 이름을 보여주지 않고 이전을 차단합니다.

부모 BF/PA가 사라진 과거 orphan 행은 데이터 보존 원칙에 따라 로컬에 남깁니다. V7 관계 검사를 통과하지 못하는 행은 새로 서버에 올리지 않고 분석·기록 화면에서도 기존 canonical 규칙에 따라 제외합니다.

### 계정별 백업·복원

- 내보내기에는 현재 UID의 기록만 포함합니다.
- 백업에 `exportOwnerId`, 앱/스키마 버전, 생성 시각, 가린 이메일을 기록합니다.
- 다른 UID의 V7 백업은 열기 전에 차단합니다.
- 소유자가 없던 V6 백업은 현재 계정으로 가져올 수 있습니다.
- 복원 전에 선수·경기·이벤트·훈련 수와 날짜 범위를 미리 보여줍니다.
- `병합`과 `전체 교체`를 분리했습니다.
- 어느 방식을 선택해도 복원 직전에 현재 계정 백업을 자동으로 내려받습니다.

### 오프라인·로그아웃·충돌 처리

- 오프라인 변경은 현재 UID 전용 DB에 `dirty` 상태로 남습니다.
- A가 로그아웃해도 A의 미동기화 기록은 A DB에 보관되며 B에게 보이지 않습니다.
- `로그아웃하고 이 기기 캐시 삭제`는 미동기화 기록이 0건일 때만 허용합니다.
- 서버 관계 검사를 통과하지 않아 로컬에만 보존된 기존 행이 있으면 캐시 삭제 전에 현재 계정 전체 백업을 자동으로 내려받습니다.
- 캐시 삭제는 기기 사본만 지우고 서버 기록은 삭제하지 않습니다.
- 동기화는 서버와 로컬의 `client_updated_at`을 비교해 더 최근 저장을 사용합니다.
- 충돌이 있으면 적용한 최신 기록 수를 안내합니다.
- 네트워크·세션 만료·RLS·테이블 미설치·서버 지연 오류를 구분해 표시합니다.

### 서버 관계 무결성

`migration_v7.sql`은 기존 행을 삭제하지 않고 다음을 추가합니다.

- `owner_id` 중심 인덱스
- 모든 테이블의 RLS/권한 재확인
- anon 역할의 데이터 테이블 권한 철회
- 선수 ↔ 경기일 ↔ BF/PA ↔ 이벤트 간 owner/athlete/game-day 일치 검사
- 부모 BF가 있는 이벤트는 투구 도메인만 허용
- 부모 PA가 있는 이벤트는 타격 도메인만 허용
- 활동 날짜와 경기일 날짜 일치 검사
- 계정 삭제 시 기존 FK의 cascade 유지

2. GitHub Pages 파일을 V7.9.0 파일로 교체합니다.

4. 투구·타격·주루·수비의 경기 상황 입력·수정·기록 표시·상황별 분석을 확인합니다.

V7.9.0에는 신규 migration이 없습니다. V7.1 이하에서 바로 올리는 경우에는 기존 강판 동기화를 위해 `migration_v8.sql`까지 적용해야 합니다.

## V6에서 바로 업그레이드

1. 기존 V6.5.2에서 JSON 백업을 한 번 내려받습니다.
2. Supabase SQL Editor에서 `migration_v7.sql`, `migration_v8.sql` 순서로 실행합니다.
3. GitHub Pages 파일을 V7.9.0 파일로 교체합니다.
4. Supabase Auth를 초대 전용으로 설정하고 Site URL / Redirect URL을 실제 GitHub Pages 주소로 맞춥니다.
5. 앱을 다시 열고 기존 계정으로 로그인합니다.
6. 기존 기기 기록 미리보기가 나오면 내용을 확인한 후 `내 계정으로 이전`을 선택합니다.
7. 설정에서 동기화 대기 0건과 마지막 동기화 시각을 확인합니다.
8. A/B 두 계정으로 같은 기기에서 번갈아 로그인해 데이터가 분리되는지 확인합니다.

기존 V6 전역 DB와 서버의 V6 테이블은 삭제하지 않습니다. 문제가 생기면 이전 ZIP과 기존 로컬 원본으로 되돌릴 수 있습니다.

## 신규 설치

1. `migration_v6.sql` 실행
2. `migration_v7.sql` 실행
3. `migration_v8.sql` 실행
4. `supabase-config.js`에 Project URL과 Publishable key 입력
5. `AUTH_SETUP.md`에 따라 초대 전용 Auth 설정
6. GitHub Pages 배포

`supabase-config.js`에는 브라우저용 `publishable` 또는 legacy `anon` key만 둡니다. `service_role`, `sb_secret_...` 키는 절대 코드나 GitHub에 넣지 마세요.

## V6.5 분석·기록 규칙 유지

- 공식 투구 이벤트는 활성 BF 부모가 있어야 홈·기록·분석에 포함됩니다.
- 타격 투구 이벤트는 활성 PA 부모가 있어야 포함됩니다.
- 견제·경기 연습투구·수비·주루는 원래 부모가 없으므로 그대로 유효합니다.
- orphan 행은 삭제하지 않고 일반 화면·통계에서만 제외합니다.
- 경기별/주간/월간/연간 추이와 경기/훈련 분석 대시보드를 그대로 유지합니다.
- Strike%, CSW%, AVG, OBP 등 기간 비율은 구간별 퍼센트 평균이 아니라 해당 기간의 분자/분모 합계로 다시 계산합니다.
