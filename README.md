# 야구일기 V7.4.0

야구일기는 한 선수의 경기·훈련·투구·타격·수비·주루를 한 공 한 공 쌓아 보는 오프라인 우선 PWA입니다.

V7.4.0은 기록 카드의 결과를 더 빠르게 읽을 수 있게 재배치하고, 기록 검색과 분석 날짜 이동을 실제 조건에 맞는 기록일 중심으로 개선한 UI 업그레이드입니다. 데이터베이스 스키마와 Supabase SQL은 변경하지 않습니다.

## V7.4.0 핵심 변경

### 결과 중심 기록 카드

- 투구·타격 카드에서 화면상 `#3`, `3 PA` 같은 순번을 제거하고 같은 자리에 `K`, `2B`, `미완료`, `현재 타자`, `수정 중`, `결과 미상`, `강판 중단` 같은 결과·상태를 색상 배지로 표시합니다. 내부 순번 데이터는 그대로 보존합니다.
- 카드 가운데에는 `우투 · 상대 좌타 / 4구`처럼 투타 조건과 투구 수를 한 줄로 표시하고, 오른쪽 화살표로 공별 기록과 수정·삭제 동작을 펼칩니다.
- 수비 카드는 포구와 송구 결과를 서로 다른 색상 배지 두 줄로 표시합니다. 카드 가운데에는 `SS · 백핸드 / 1루 송구`를 표시하며 상세 화면에서 TLU와 수정·삭제를 확인합니다.
- 주루 카드는 성공·실패 배지와 `도루 · 1루 → 2루` 구간을 표시하고, 펼침 단계 없이 수정·삭제 버튼을 바로 제공합니다.
- 수비·주루 카드에서는 의미가 적었던 입력 시각을 표시하지 않습니다. 기록 시각 데이터 자체는 유지합니다.

### 기준일·기간·상세 조건 기록 검색

- 기록 화면에 분석과 같은 기준일, 이전·다음 기록일, `1/7/30/90일·시즌·누적` 조회 기간을 추가했습니다.
- 경기·훈련과 투구·타격·수비·주루를 먼저 고르고, 적용 가능한 상세 조건만 동적으로 표시합니다.
- 투구·타격은 완료·진행 중·미완료·결과 미상 상태와 본인/상대 투타 방향으로 찾을 수 있습니다. 투구에는 강판 중단 조건도 제공합니다.
- 수비는 포구 성공·불안정·실패와 송구 성공·악송구·없음, 주루는 성공·실패로 찾을 수 있습니다.
- 공마다 투타 방향이 달라진 기록은 일치하는 공만 강조하고 다른 공은 흐리게 표시하며 `조건 일치 n/m구`를 함께 보여줍니다.

### 실제 기록일 기준 분석 이동

- 분석의 이전·다음 버튼은 현재 경기/훈련, 종목, 투타 상세 조건에 실제 데이터가 있는 날짜만 이동합니다.
- 빈 경기일 행이나 다른 종목만 기록된 날짜는 후보에서 제외합니다.
- 날짜 입력창으로 기록이 없는 날짜를 직접 선택하는 기능은 유지합니다.

## V7.3.0 핵심 변경

### 날짜가 지난 미완료 기록

- 오늘의 마지막 미완료 BF/PA만 `현재 타자` 또는 `현재 타석`으로 표시합니다.
- 날짜가 지나면 데이터를 덮어쓰지 않고 화면에서 `미완료 기록`으로 계산해 표시하며 `계속 입력` 버튼을 제공합니다.
- `계속 입력`을 누른 기록은 `수정 중`으로 구분합니다. 과거 날짜에 새 기록을 실수로 이어 붙이지 않도록 명시적으로 재개한 경우에만 기존 BF/PA를 이어갑니다.
- 앱을 자정 넘겨 열어 둔 경우와 백그라운드에서 다시 연 경우에도 날짜를 다시 확인해 상태를 갱신합니다.

### 입력 화면 배치와 지표 요약

- 넓은 화면은 기존처럼 왼쪽 지표·오른쪽 입력의 2열을 유지합니다.
- 태블릿 세로와 모바일의 1열 화면은 지표가 위, 입력이 아래에 나타납니다.
- 낮은 가로 화면이 720px 이상이면 압축 2열 배치를 유지합니다.
- 지표 패널은 모바일 1열에서 핵심 지표 4개만 기본 표시하며 `상세 보기`로 전체 지표를 펼칠 수 있습니다.
- 사용자가 선택한 접기·펼치기 상태는 해당 브라우저에 저장됩니다.

## V7.2.0 핵심 변경

### 입력 UI와 공별 투타 방향

- 투구의 `투구 방향 / 상대 타자`, 타격의 `타격 방향 / 상대 투수` 선택을 좌측 요약 패널에서 우측 입력 카드 상단으로 옮겼습니다.
- V7.2 당시 태블릿 세로와 모바일 단일 열에서는 입력 카드가 경기 요약보다 먼저 나타났습니다. V7.3부터는 지표가 위, 입력이 아래로 표시됩니다. 낮은 가로 화면의 압축 2열과 모바일 투타 선택 한 열 배치는 유지됩니다.
- `내 우투`, `내 좌투`처럼 어색한 표현을 없애고 `투구 방향`, `타격 방향`으로 통일했습니다.
- 투수나 타자의 방향을 바꾸면 다음 공부터 적용됩니다. 타격에서 별도의 투수 교체 이벤트를 만들지 않습니다.
- BF/PA 묶음은 카운트와 결과를 위해 유지하지만, 실제 투타 방향은 각 공의 metadata에 저장합니다.
- 펼친 BF/PA 기록에서 각 공의 `우투 → 좌타` 형식을 확인하고, 공 수정 화면에서 해당 공의 투타 방향도 고칠 수 있습니다.
- 과거 기록처럼 공에 방향 metadata가 없으면 BF/PA 부모 방향으로 자동 보완합니다. 공에 명시적으로 `미입력`을 저장한 경우에는 과거 부모 값으로 덮지 않습니다.

### 분석 기준

- Strike%, CSW%, Swing%, Contact% 같은 공 기반 지표는 각 공에 저장된 방향으로 좌우 스플릿합니다.
- K%, BB%, AVG, OPS처럼 BF/PA 결과가 필요한 지표는 결과가 확정된 마지막 공의 방향을 사용합니다.
- P/BF와 P/PA는 마지막 공 방향이 조건에 맞는 정상 완료 BF/PA를 고른 뒤, 그 BF/PA 안의 전체 공 수로 계산합니다.
- 방향 미입력 공은 전체 집계에는 포함하고 우·좌 조건 분석에서는 제외합니다. 분석의 데이터 상태에 미입력 공 수를 표시합니다.

### 강판 기록

- 경기 투구 입력에 전체 너비 `강판 기록`을 추가했습니다.
- 타자 상대 중 강판하면 해당 BF를 `RELIEVED · 강판 중단`으로 보존합니다. 이미 입력한 공은 Official Pitches, 공 기반 비율, TLU에는 포함하지만 완료 BF, K/BB%, P/BF 분모에는 넣지 않습니다.
- 타자 사이에 강판하면 BF를 만들지 않고 강판 시점 이벤트만 기록합니다.
- 강판 후에도 투구 입력은 잠기지 않으며 다음 공은 새 BF로 시작합니다.
- 최근 기록과 전체 기록에서 강판을 확인하고 취소할 수 있습니다. 타자 상대 중 강판을 취소하면 중단했던 BF를 다시 이어서 입력할 수 있습니다.

### 이번 버전에서 유지한 범위

- 기존 `오늘 기본 기준일 · 이전/다음 기록일 · 1/7/30/90일/시즌/누적` 분석 UI와 수비 적용 범위는 변경하지 않았습니다.
- 수비 입력 구조와 수비 전용 분석 지표는 변경하지 않았습니다.
- 주루 입력, 계정 동기화/로그아웃 UI, 설치 앱 아이콘 파일과 manifest는 V7.1 상태를 그대로 유지했습니다.
- 날짜 하나당 경기 1/경기 2를 나누는 구조는 추가하지 않았습니다.

## V7.0.0 핵심 변경

### 로그인 필수 / 초대 전용

- 로그인 세션이 없으면 기록 화면과 로컬 기록 DB를 열지 않습니다.
- 앱 안의 계정 만들기 기능을 제거했습니다.
- Supabase Dashboard에서 초대한 이메일만 사용하도록 운영합니다.
- 초대 링크와 비밀번호 재설정 링크를 앱에서 처리합니다.
- 초대 수락 시 새 비밀번호 설정 화면을 표시합니다.
- 한 번 로그인하면 세션을 유지하며, 이미 로그인한 계정은 오프라인에서도 기록할 수 있습니다.

Supabase의 신규 가입 허용 설정은 Dashboard에서 직접 꺼야 합니다. 자세한 순서는 `AUTH_SETUP.md`를 확인하세요.

### 계정별 IndexedDB 완전 분리

로그인 UID별로 별도 DB를 사용합니다.

- A 계정: `baseball-diary-v7:<A_UID>`
- B 계정: `baseball-diary-v7:<B_UID>`

로그아웃하면 동기화 타이머를 중단하고, 활성 DB를 닫고, 화면 메모리와 모달 내용을 비웁니다. 이후 B 계정으로 로그인하면 B 전용 DB만 열기 때문에 같은 아이폰·태블릿을 번갈아 사용해도 A 기록이 B 화면·분석·백업에 나타나지 않습니다.

저장 모듈도 현재 UID와 다른 `ownerId` 행의 쓰기를 거부합니다. 서버에서는 기존 `owner_id` RLS가 별도의 보호벽으로 동작합니다.

### 기존 기록의 안전한 1회 이전

V6의 전역 IndexedDB `baseball-tracker-v6` 또는 V5 로컬 기록을 발견하면 자동 귀속하지 않고 먼저 미리보기를 표시합니다.

- 선수 수
- 경기 일수
- 경기 이벤트 수
- 훈련 세트 수
- 기록 기간

`내 계정으로 이전`을 선택한 경우에만 현재 UID로 복사하고 동기화합니다. 기존 전역 DB는 자동 삭제하지 않습니다.

기존 전역 DB에 여러 계정이 섞여 있으면 현재 UID 소유 행과 그 선수·경기 관계로 소유자를 확인할 수 있는 행만 분리해 미리보기에 표시합니다. 다른 계정 행은 읽거나 이전하지 않습니다. 현재 계정으로 확인되는 행이 하나도 없으면 기록 수나 선수 이름을 보여주지 않고 이전을 차단합니다.

부모 BF/PA가 사라진 과거 orphan 행은 데이터 보존 원칙에 따라 로컬에 남깁니다. V7 관계 검사를 통과하지 못하는 행은 새로 서버에 올리지 않고 분석·기록 화면에서도 기존 canonical 규칙에 따라 제외합니다.

### 계정별 백업·복원

- 내보내기에는 현재 UID의 기록만 포함합니다.
- 백업에 `exportOwnerId`, 앱/스키마 버전, 생성 시각, 가린 이메일을 기록합니다.
- 다른 UID의 V7 백업은 열기 전에 차단합니다.
- 소유자가 없던 V6 백업은 현재 계정으로 가져올 수 있습니다.
- 복원 전에 선수·경기·이벤트·훈련 수와 날짜 범위를 미리 보여줍니다.
- `병합`과 `전체 교체`를 분리했습니다.
- 어느 방식을 선택해도 복원 직전에 현재 계정 백업을 자동으로 내려받습니다.

### 오프라인·로그아웃·충돌 처리

- 오프라인 변경은 현재 UID 전용 DB에 `dirty` 상태로 남습니다.
- A가 로그아웃해도 A의 미동기화 기록은 A DB에 보관되며 B에게 보이지 않습니다.
- `로그아웃하고 이 기기 캐시 삭제`는 미동기화 기록이 0건일 때만 허용합니다.
- 서버 관계 검사를 통과하지 않아 로컬에만 보존된 기존 행이 있으면 캐시 삭제 전에 현재 계정 전체 백업을 자동으로 내려받습니다.
- 캐시 삭제는 기기 사본만 지우고 서버 기록은 삭제하지 않습니다.
- 동기화는 서버와 로컬의 `client_updated_at`을 비교해 더 최근 저장을 사용합니다.
- 충돌이 있으면 적용한 최신 기록 수를 안내합니다.
- 네트워크·세션 만료·RLS·테이블 미설치·서버 지연 오류를 구분해 표시합니다.

### 서버 관계 무결성

`migration_v7.sql`은 기존 행을 삭제하지 않고 다음을 추가합니다.

- `owner_id` 중심 인덱스
- 모든 테이블의 RLS/권한 재확인
- anon 역할의 데이터 테이블 권한 철회
- 선수 ↔ 경기일 ↔ BF/PA ↔ 이벤트 간 owner/athlete/game-day 일치 검사
- 부모 BF가 있는 이벤트는 투구 도메인만 허용
- 부모 PA가 있는 이벤트는 타격 도메인만 허용
- 활동 날짜와 경기일 날짜 일치 검사
- 계정 삭제 시 기존 FK의 cascade 유지

## V7.3.0에서 V7.4.0으로 업그레이드

1. 설정에서 동기화 대기 0건을 확인하고 현재 계정 JSON 백업을 내려받습니다.
2. GitHub Pages 파일을 V7.4.0 파일로 교체합니다.
3. 기존 앱 탭과 설치 앱을 완전히 닫았다가 다시 열어 V7.4 Service Worker를 활성화합니다.
4. 결과 중심 기록 카드, 기록 상세 검색, 분석 이전·다음 기록일 이동을 확인합니다.

V7.4에는 신규 migration이 없습니다. V7.1 이하에서 바로 올리는 경우에는 기존 강판 동기화를 위해 `migration_v8.sql`까지 적용해야 합니다.

## V6에서 바로 업그레이드

1. 기존 V6.5.2에서 JSON 백업을 한 번 내려받습니다.
2. Supabase SQL Editor에서 `migration_v7.sql`, `migration_v8.sql` 순서로 실행합니다.
3. GitHub Pages 파일을 V7.4.0 파일로 교체합니다.
4. Supabase Auth를 초대 전용으로 설정하고 Site URL / Redirect URL을 실제 GitHub Pages 주소로 맞춥니다.
5. 앱을 다시 열고 기존 계정으로 로그인합니다.
6. 기존 기기 기록 미리보기가 나오면 내용을 확인한 후 `내 계정으로 이전`을 선택합니다.
7. 설정에서 동기화 대기 0건과 마지막 동기화 시각을 확인합니다.
8. A/B 두 계정으로 같은 기기에서 번갈아 로그인해 데이터가 분리되는지 확인합니다.

기존 V6 전역 DB와 서버의 V6 테이블은 삭제하지 않습니다. 문제가 생기면 이전 ZIP과 기존 로컬 원본으로 되돌릴 수 있습니다.

## 신규 설치

1. `migration_v6.sql` 실행
2. `migration_v7.sql` 실행
3. `migration_v8.sql` 실행
4. `supabase-config.js`에 Project URL과 Publishable key 입력
5. `AUTH_SETUP.md`에 따라 초대 전용 Auth 설정
6. GitHub Pages 배포

`supabase-config.js`에는 브라우저용 `publishable` 또는 legacy `anon` key만 둡니다. `service_role`, `sb_secret_...` 키는 절대 코드나 GitHub에 넣지 마세요.

## V6.5 분석·기록 규칙 유지

- 공식 투구 이벤트는 활성 BF 부모가 있어야 홈·기록·분석에 포함됩니다.
- 타격 투구 이벤트는 활성 PA 부모가 있어야 포함됩니다.
- 견제·경기 연습투구·수비·주루는 원래 부모가 없으므로 그대로 유효합니다.
- orphan 행은 삭제하지 않고 일반 화면·통계에서만 제외합니다.
- 경기별/주간/월간/연간 추이와 경기/훈련 분석 대시보드를 그대로 유지합니다.
- Strike%, CSW%, AVG, OBP 등 기간 비율은 구간별 퍼센트 평균이 아니라 해당 기간의 분자/분모 합계로 다시 계산합니다.
